# 架构与扩展

工程将界面、受限桌面接口和本地服务分开。React 只展示数据及发起固定操作；文件访问、授权检查、备份和子进程均位于 Electron 主进程。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `src/App.tsx` | 总览、同步、备份、活动与集成页面；详情面板和差异预览 |
| `src/shared.ts` | Agent ID、视图、配置、同步计划及 IPC 接口类型 |
| `electron/adapters.ts` | 六个内置适配器的显示信息、候选路径和能力标签 |
| `electron/preload.ts` | 通过 `contextBridge` 暴露固定 `consoleApi`，不暴露 Node 或原始 IPC |
| `electron/main.ts` | 窗口、单实例、IPC 来源和参数检查、原生路径选择及确认框 |
| `electron/service.ts` | 路径绑定、状态快照、同步计划、备份恢复、活动台账 |
| `electron/safety.ts` | 本地路径与链接检查、文本限制、目录遍历、哈希和原子文件替换 |
| `electron/processes.ts` | 原生 EXE 启动、所属子进程状态、停止和输出缓冲 |

界面没有本地权限时会显示桌面启动提示。主进程只接受来自预期窗口主 frame 和预期页面 URL 的 IPC。会改变状态的 IPC 操作串行处理；刷新快照可以并行读取。

## 状态与发现

适配器列出候选记忆文件、技能目录及 EXE。用户绑定优先于候选路径；未绑定时选择第一个存在的候选，没有候选存在则显示第一个待发现路径。候选扫描只读，不执行程序、不注册服务，也不构成同步授权。

`ready` 表示记忆和技能路径存在且检查通过，`partial` 表示至少发现一个路径或程序，`missing` 表示均未发现，`attention` 表示读取或安全检查失败。进程状态单独保存，只来自本控制台本次运行创建的直接子进程。

记忆使用文件字节的 SHA-256 比较；字符数按 Unicode 码点统计。技能数是安全遍历范围内名为 `SKILL.md` 的文件数量，不验证技能语义或厂商加载结果。

## 同步与恢复

1. 共享源和目标通过原生路径选择器绑定。目标写入权限只来自持久化的明确绑定。
2. `preview()` 生成逐文件计划：来源、目标、旧/新内容、哈希和大小。技能路径按来源相对目录映射。
3. 计划仅存于内存，有效期五分钟。创建新计划会替换旧计划；保存路径配置会清空计划。
4. 用户检查预览并确认后，主进程再次显示实际目标列表。
5. `apply()` 检查计划、授权配置、源/目标哈希和活动链，先备份全部现有目标，再逐文件重新检查并写入。
6. 每个文件在目标同目录创建临时文件，写入、刷新后重命名替换，并校验结果、记录日志。

多文件操作不是事务。若中途失败，已完成的文件会保留，现有目标可通过自动快照恢复；新增文件不会因恢复而删除。恢复读取快照清单、检查备份内容哈希，再走相同的预览和写入流程。撤销或更换授权后，旧快照只能恢复到仍被当前配置明确授权的目标。

## 数据生命周期

配置、台账和快照位于 `userData/console-data`。应用不清理旧快照；界面最多展示最近 100 份快照和最近 100 条活动。台账采用含序号、时间、上条哈希和本条哈希的 JSONL 记录；它可检测部分意外损坏，但没有外部签名或可信锚点。

同步计划、当前子进程对象与 CLI 输出只保留在内存。关闭应用时若仍有所属进程，会要求用户返回或放弃追踪；应用不会自动杀死这些进程。

## 添加适配器

当前扩展方式是编辑源码后重新构建，没有加载任意第三方插件代码的机制。

1. 在 `src/shared.ts` 的 `AgentId` 中增加 ID。
2. 在 `electron/adapters.ts` 注册名称、说明、外观、候选位置和能力。没有确认的厂商路径用空数组，无法验证的能力标为 `candidate`。
3. 通用桌面应用使用 `mode: 'desktop'`。目前 `mode: 'cli'` 专用于 Claude 的固定 `-p` 协议；新 CLI 必须先在主进程增加独立的参数与输入校验，不能直接复用此模式假定兼容。
4. 为新发现逻辑、输入限制和关键错误路径增加测试，更新集成文档。
5. `src/App.tsx` 中总数和部分摘要当前使用六个适配器的常量；扩展时应统一改为注册表或快照中的长度。

适配器不得自行获得写权限、引入 shell 字符串、默认执行技能脚本或宣称未验证的厂商协议支持。需要新的登录、任务派发等能力时，应新增有明确输入类型和授权边界的主进程 API。

## 验证与交付

先运行 `npm test` 和 `npm run build`，再对构建产物运行 `npm run test:desktop`。`npm run pack` 与 `npm run dist` 使用 electron-builder 输出 Windows x64 解包目录及便携 EXE；构建直接使用 `node_modules/electron/dist` 的已安装运行时。解包成品使用 `node tests/packaged.cjs`，便携单文件使用 `node tests/portable.cjs` 验证启动。依赖由 `package-lock.json` 锁定，使用 `npm ci` 安装，Electron 当前固定为 `45.0.0`。写入测试使用隔离数据，不连接真实厂商账户来模拟业务结果。覆盖、成品只读发现范围与结果见 [测试说明](TESTING.md)。

开发模式提供 `CONSOLE_TEST_DATA` 和 `CONSOLE_TEST_HOME` 环境变量供测试隔离数据与用户目录；打包应用不接受这两项覆盖。请勿把测试变量配置在日常启动环境中。
