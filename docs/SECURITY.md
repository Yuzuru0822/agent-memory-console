# 安全边界

本工程面向当前 Windows 用户的本地文件与进程操作，重点防止误写路径、过期预览执行和把界面输入拼接为系统命令。它不是不可信 EXE 的沙箱，也不是具有管理员级防篡改能力的审计系统。

## 桌面与 IPC

- 渲染进程关闭 Node 集成，开启 `contextIsolation`、沙箱和 `webSecurity`，禁用 webview。
- preload 仅暴露固定方法；主进程检查窗口、主 frame、页面 URL、Agent ID 和参数类型。
- 阻止新窗口、非预期页面导航和浏览器权限请求。生产界面来自打包的本地文件，开发服务器仅监听 `127.0.0.1`。
- CSP 限制脚本、连接及资源来源。文本差异与 CLI 输出按文本渲染，不作为 HTML 执行。
- 路径授权、同步写入、程序启动和停止使用主进程原生确认框；默认选项为取消。手动快照只读取已授权目标并写入控制台自己的备份目录。

这些措施参考 [Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)。当前工程仍使用本地文件协议加载生产界面，没有配置 Electron fuses 或代码签名；发布者应持续检查依赖和运行时更新，不能把上述设置视作完整安全认证。

## 路径和内容限制

以下原有文本同步限制适用于“共享源同步 · 兼容模式”。统一仓库采用后续章节的完整文件包限制；两种操作分别检查授权与预览，不能用一个流程绕过另一流程的边界。

| 项目 | 当前限制 |
| --- | --- |
| 路径 | 必须是本地绝对路径；拒绝磁盘根、UNC/设备路径和 Windows 备用数据流 |
| 技能链接 | 可检查本地目录或文件符号链接、junction；单条解析最多跟随 40 个链接；同步与备份要求确认实际根目录和链接映射，并在使用前重新解析 |
| 其他路径 | 记忆文件、普通 EXE 和工作目录继续拒绝路径中的符号链接与 junction；npm 安装另有受限解析规则 |
| 记忆 | 已存在的 UTF-8 `.md` 普通文件，不接受 NUL 字节 |
| 同步或备份的单个文本文件 | 不超过 1 MiB |
| 技能文本 | 仅 `.md`、`.txt`、`.json`、`.yaml`、`.yml` |
| 技能只读检查 | 不读取正文；实际文件和目录去重，最多 20,000 个条目、20 层；超过范围或遇到断链、循环时显示不完整警告 |
| 技能文本同步 | 最多 200 个文本文件、16 MiB，目录最多 20 层；不以此限制技能数量统计 |
| 排除项 | 隐藏条目、`node_modules`、`dist`、`build`、脚本和二进制 |
| 单次同步 | 所有目标合计最多 200 个文件、16 MiB |
| 可写范围 | 仅绑定的单个记忆文件，以及已绑定技能目录和当前已授权链接实际目标中的允许文本 |
| 保护目录 | 拒绝写入控制台数据目录、应用目录、Windows 目录及 Program Files 目录 |

目标目录不能与共享技能源相同或互相包含；重叠判断使用解析后的实际位置。同一次计划中两个 Agent 也不能写入同一个实际目标。目录发现本身只读，存在候选文件或链接并不授予写权限。撤销授权后候选路径仍可被发现，但不能继续同步。

符号链接和 junction 只作为定位入口。确认框展示逻辑目录、实际根目录及链接映射；旧版本仅保存路径的授权不会自动授权链接目标。源链接中的文本被读取并复制，目标通过实际路径执行原子写入，链接对象本身保留。链接改指、出现新的未授权映射、断链或循环会阻止相关写入，需核对并重新授权。所有实际写入目标仍受本地路径与保护目录规则约束。多个 Agent 指向同一目录时，写入会影响每个引用方。

检查与写入之间仍存在操作系统层面的竞争窗口；文件授权不是抵御同一用户恶意程序的安全边界。本实现没有通用的文件系统重解析点防护驱动，也不保证识别所有特殊存储提供程序行为。重要资料应保留独立备份。

## 预览、备份与恢复

计划五分钟后失效，并绑定生成时的配置、逻辑路径和实际路径。写入前重新解析全部链接映射；逐文件写入时再次校验路径、来源与目标哈希，避免把预览后的变更覆盖掉或写入改指后的目标。现有目标全部先备份，再通过实际目标同目录临时文件与重命名进行单文件替换；写入结果再次校验，原有链接保留。

多文件批次不保证事务性。发生磁盘、权限或并发错误时，批次可能部分完成，活动日志会记录已完成数量。快照同时记录逻辑目标与实际目标；恢复时按当前授权重新解析，旧快照不能授予旧链接目标新的访问权。恢复只还原快照中存在的文件，仍需当前授权和预览确认；不会删除之后新增的文件，也不会自动恢复整个目录或进程状态。

所有快照、配置和台账保存在本机明文，没有密码加密。备份可能包含敏感记忆、内部说明和路径，应与原始文件采用相同的访问保护。统一仓库的备份可以按显式保存的保留策略清理，见下节；不会自动删除记忆或技能。

## 统一仓库、双向合并与 junction 迁移

- 中央仓库必须是独立的本地目录。初始化只接受空目录或带本应用标识的受管仓库，不接管用户已有代码仓库。仓库根与内部文件不允许链接，中央 `.git` 不允许外部对象存储、共享工作树或非预期 HEAD。中央版本管理只使用 `main` 分支及规定路径；技能内独立 Git 仓库的历史按下述规则保留。
- Git 由固定版本 isomorphic-git 在主进程执行，读写经过目录范围和容量限制，不调用 Git CLI、shell 或 hooks；没有 fetch、push 或网络客户端。
- 双向同步每次最多 5,000 个文件、256 MiB，单文件最多 32 MiB。记忆目录仅纳入 `.md/.txt/.json/.yaml/.yml`；技能可包含脚本和二进制，但不执行。UTF-8 文本不超过 1 MiB 才尝试文本合并；行数和比较量也受限，超出时需要选择版本。
- 同步共同版本独立于 Git 提交保存。无共同版本的不同内容、无法安全合并的文本和二进制冲突不能被静默覆盖。手动同步需预览、完整冲突选择和原生确认；自动模式只处理无需人工选择的内容，冲突保留待处理。
- 任何一端文件缺失都不会作为删除指令传播；内容从仍保留的一端补回。两个独立目录之间的这一保证不改变 junction 的语义：连接后的 Agent 与仓库访问同一文件，Agent 自行删除文件会直接删除仓库工作文件，应通过 Git 版本或备份恢复。
- 技能迁移预览重新检查源文件、目标文件、完整目录证据和链接映射。允许正常本地链接；失效和循环入口不导入，保留在原目录并显示警告；网络、设备和受保护位置仍拒绝。完整技能包限制为 5,000 个文件、256 MiB；普通单文件 32 MiB，仅 `.git/objects/pack/*.pack` 放宽至 128 MiB，仍计入总量。
- 显式迁移可携带技能根或子目录中的普通 `.git` 目录，保留提交历史、分支和远程配置。元数据只保存字节，不执行 hooks、远程操作或其中配置的命令；预览显示保留的 Git 仓库数量，不展示配置正文。目标同名 `.git` 必须完整元数据相同才可复用；不同则整仓库冲突，在任何写入前拒绝，不能逐文件拼接。需先统一双方的仓库版本，或使用不同的技能子目录。
- 内层仓库必须是独立完整工作树。拒绝外置 `.git` 指针文件，以及 `.git` 中的 `commondir`、`gitdir`、`worktrees`、`modules`、`objects/info/alternates`、`objects/info/http-alternates`。配置 `include/includeIf`、`core.worktree`、`core.hooksPath`、`extensions.partialClone`、`remote.*.promisor` 也会阻止迁移；应先转为对象与配置完整、不依赖原位置的独立 clone。Git 配置需为不超过 1 MiB 的有效 UTF-8 普通文件；无法安全检查的格式拒绝。
- Git 元数据内不允许符号链接、junction 或 `.lock` 锁。遇到锁应等待 Git 操作完成，或确认残留锁已安全处理后再迁移。原有路径和链接检查继续执行；此能力不授权读取外置 Git 元数据或对象库。
- 中央 Git 只记录工作文件，排除技能内层 `.git` 与 gitlink；中央提交不会保存内层 Git 元数据。独立副本的手动与自动同步均不合并或传播 `.git`，普通技能文件继续参与双向同步。原技能备份保留完整元数据且不参与自动清理。junction 连接后，各入口直接访问同一份内层 Git；用户自行执行的 Git 操作不受控制台的同步规则约束。
- 导入完成后，将 Agent 原技能入口改名保存在同一父目录，再创建指向仓库 skills 的 junction。没有先删除原目录。覆盖仓库同名内容前另存原字节。解除连接只移除核验过的 junction 入口并恢复原入口，不遍历删除仓库；原目录或入口被外部改动时拒绝继续。
- 自动同步默认关闭，间隔支持 30–3,600 秒；默认 60 秒。启用与设置变更经过原生确认。自动清理仅处理受管过期备份与临时文件，默认保留 30 天且至少 20 份；不会清理记忆、技能、Git 历史或 junction 迁移原目录。退出应用后定时执行停止。

原子替换仍只保证单文件；多文件同步不是文件系统事务。迁移失败尝试回滚已写入项及入口，若其他程序在操作期间改动文件，保留现场和备份并报告恢复位置。Windows 同用户并发程序的竞争窗口仍存在；不声称提供管理员级文件系统隔离。

## 进程启动与停止

通用程序只接受显式绑定的本地 `.exe`；Claude 另支持授权受限 npm 安装描述。绑定时以及每次启动前，`nativeExecutable()` 都检查普通文件类型、DOS `MZ` 头、PE 头偏移与 `PE\0\0` 签名、可执行标志、非 DLL 标志，以及 PE32/PE32+ optional header magic。它未进行完整 PE 解析或机器架构兼容性校验，格式检查通过也不能证明程序可以运行、厂商身份可信或内容安全。应用不校验 Authenticode 签名、不请求管理员权限，也不代管凭据。

npm 支持限定为 `claude.cmd` 旁包名严格匹配的 `@anthropic-ai/claude-code`，且仅接受 `cli.js` 或 `bin/claude.exe` 两种入口。CMD 正文从不执行或解析。元数据上限 64 KiB，旧版 JS CLI 为非空 UTF-8 普通文件、上限 32 MiB；这与记忆同步的 1 MiB 限制分开。npm 外层 prefix 和 Node 的 nvm junction 仅在解析安装时规范化，实际路径再经检查，包内及入口链接拒绝；技能目录链接由前述独立授权规则处理。启动前重新解析并比对已授权的实际路径，入口和 Node 改变必须重新授权。同一路径的包内容升级允许，仍不构成可信签名验证。

进程使用 `spawn` 和 `shell: false`，不拼接 shell 命令，不接受任意启动参数。Claude 使用固定 `-p`，任务正文经标准输入传入，最多 16,000 字符。不会添加跳过权限审批的参数。第三方程序继承当前用户的权限与环境，可以按照其自身行为联网、访问文件和计费。

npm 子进程清除 `NODE_OPTIONS`、`NODE_PATH` 和 `ELECTRON_RUN_AS_NODE`，防止继承 Node 启动钩子；其他环境设置继续继承，包括用户的提供商配置。旧版启动形如 `spawn(nodeExe, [cliJs, '-p'])`，新版为 `spawn(packageExe, ['-p'])`。启动确认展示实际程序及需要时的 CLI 脚本路径。npm 发现、授权和版本检查不证明账户或任务调用成功。

停止只针对控制台保存的直接子进程句柄，不通过名称或 PID 搜索结束其他程序，不执行进程树终止。停止可能打断未保存工作。控制台关闭后会失去追踪，第三方程序可能继续运行；桌面启动器派生的独立子进程本来就不在跟踪范围内。

## 日志与隐私

活动台账记录路径授权、备份、文件写入及进程事件。它包含本地路径、进程 PID 和退出结果，不保存 Claude 任务正文。CLI 输出仅在内存中保留最近 32,000 字符，并作为文本显示。

日志用 SHA-256 哈希链检查内容及顺序的一致性，不能证明操作者身份，也不能防止同一用户重新生成整条链、删除日志或截断末尾。它用于发现意外损坏，不提供不可否认性。校验失败会阻止同步写入、备份、启动和路径授权变更；超过 32 MiB 也会要求归档。界面显示最近 100 条，磁盘保存完整未归档台账。

控制台没有遥测、账户服务或云端上传实现。npm 安装、构建工具下载以及用户启动的第三方 Agent 可能访问网络，这些行为不受界面的“本地文件管理”能力约束。

## 验证范围

单元与桌面冒烟测试使用临时目录和隔离数据，检查授权、预览冲突、备份恢复、技能链接解析与重新授权，以及其他路径的链接拒绝。具体覆盖内容与已执行结果见 [测试说明](TESTING.md)。测试通过不代表已对所有 Windows 文件系统变体、恶意本地程序或六家客户端真实账户完成安全评估。对外分发前需另行进行真实客户端验证、依赖检查和签名发布配置。
