# 自动任务设计与使用说明

v0.5.0 将已有的自动同步、备份清理、积分领取和余额监控汇入“任务中心”。本版重点解决三个使用问题：任务分散而难以判断是否运行；临时停止需要逐个改开关；关闭窗口会结束监控。实现沿用各服务已有的授权、去重和执行规则，任务中心只汇总状态、控制后续调度及导出固定报表。

真实账号的领取、到账和余额读取仍未验证。本页描述产品能力及本地控制规则，不代表所有客户端已经完成校准。领取与余额配置见 [积分说明](REWARDS.md)，构建和验证范围见 [测试说明](TESTING.md)。

v0.6.1 的冲突推荐只在人工双向同步预览中预选：仓库缺失或较旧时采用最新 Agent，支持来源清单、CSV 导出与批量更改。后台调度不会自行使用这些推荐来消除冲突；用户在预览中确认应用后，下次自动同步才能继续。普通无冲突合并与单端补齐仍按原逻辑执行。

## 后台仓库执行（v0.7.0）

统一仓库的预览、校验、备份、文件写入和 Git 保存移到独立线程执行。顶部状态条展示正在进行的阶段、已用时间和该阶段可取得的文件计数，切换页面后仍保留；Git 保存等阶段没有准确计数时不显示整体百分比或预计完成时间。文件多或磁盘慢时仍需等待，后台执行不省略安全检查。

同步预览和默认采用清单每页显示 100 项；筛选、批量勾选和 CSV 导出针对完整计划，不仅处理当前页。切换页面保留预览与选择；有效预览仍会暂缓自动同步，需要返回仓库页确认应用或关闭预览，过期则重新预览。

可以在执行期间浏览其他页面，配置修改和其他文件操作继续遵守全局串行锁。总暂停不取消已经开始的同步。自动任务实际开始及后续清理前会重新核对主进程暂停状态；已经排队但尚未开始的任务也不能越过暂停。未启用、未到期及被预览暂停的仓库 tick 直接跳过；后台总览扫描期间不会为一个无操作 tick 长时间占用修改锁。

后台线程异常时，状态条和任务中心显示错误，自动调度及后续修改停止。请核对最近操作和备份后重启，应用不会自动重发不确定的写入。正常退出会要求等待在途操作收尾；可以使用已启用的托盘隐藏窗口，但这不是取消任务。

## 统一查看与问题处理

任务列表固定包含两项仓库任务、九项领取任务和九项余额任务。尚未支持的领取平台保留“未支持自动执行”或平台自行发放说明，不因此获得 UI 操作能力。每项展示名称、原有启用状态、当前状态、等待原因，以及已有的最近/下次检查时间；支持类型筛选、文字搜索和“只看需要关注”（包含等待条件和需要处理的任务）。

| 状态 | 含义 |
| --- | --- |
| 待配置 / `unconfigured` | 仓库尚未设置，或客户端流程/余额字段尚未完成校准 |
| 未支持自动执行 / `unsupported` | 当前平台没有控制台可执行的领取流程 |
| 未启用 / `disabled` | 配置已具备，但该项自身的自动开关关闭 |
| 已暂停 / `paused` | 原本启用的任务受统一暂停控制 |
| 等待条件 / `waiting` | 已到期等待调度，或在等待其他操作、预览、客户端校准结束 |
| 等待调度 / `scheduled` | 正在等待下次检查或下个领取周期 |
| 执行中 / `running` | 服务正在处理操作，统一暂停不会中断本次操作 |
| 需要处理 / `attention` | 同步冲突、授权变化、未知领取结果、读取失败等需要检查 |

“待处理问题”依据各服务当前状态生成，使用稳定的问题标识，同一个问题不会因刷新反复堆积。来源恢复后问题随下次刷新消失。这里是当前问题清单，不是历史通知收件箱，也没有已读/忽略开关；历史操作继续保存在活动台账和各服务记录中。“前往处理”进入统一仓库或积分福利，再处理对应配置。

问题包括仓库冲突和授权变化、任务控制配置损坏、活动台账校验失败、领取结果未知或执行前异常，以及余额读取失败、过期和低余额。低余额只使用新鲜的成功采样；失败或过期的旧数值不触发低余额判定。未配置和未启用的任务显示在任务列表中，不当作执行成功。

## 总暂停与恢复

任务中心提供“暂停 15 分钟”“暂停 1 小时”“暂停直到恢复”和“恢复自动任务”。托盘的暂停项采用直到手动恢复的方式。

统一暂停只控制后续自动执行，保留每项任务原有的 `enabled`、路径授权、客户端绑定、校准和历史。它不取消已经开始的同步、Git 保存、领取结果核验或余额读取，不停止厂商进程。已有操作正常完成后，后续自动任务继续等待；手动功能仍可使用，仍受原有授权、确认和串行锁约束。

恢复总开关仅让原先启用且符合自身执行条件的任务重新进入调度。它不会开启关闭的任务、放宽授权、补足未完成的校准或解除未知领取结果的阻止。手动触发的领取仍可执行其已有的领取前后余额采样，这属于该次手动操作的完整流程。

设置保存到 `console-data/task-controls.json`。重新启动应用后，未结束的暂停仍有效；15/60 分钟暂停到期后按当前时间恢复。应用退出期间没有任务执行，重新打开后再判断是否到期。计划时间是下一次检查资格，不保证该时刻立刻执行；服务自己的间隔、客户端状态、未完成预览和串行锁仍会影响执行。

配置限于固定字段、版本和合法时间；超过 8 KiB、格式错误、链接路径或保存失败时保持暂停，并关闭托盘隐藏设置。用户检查本地数据目录后，点击“恢复自动任务”会要求确认重建控制设置。已有任务授权及各自开关不被重建。活动台账异常时，暂停仍可生效，但不能恢复自动执行或开启托盘常驻。

## 托盘常驻和彻底退出

“关闭窗口后留在系统托盘”默认关闭。用户勾选后才创建托盘并保存设置；创建失败会报错，不隐藏窗口。控制台重新打开后会恢复已保存的常驻选择，保持窗口可访问。

启用后，窗口关闭按钮只隐藏控制台；自动任务继续按原设置和总暂停状态运行。托盘菜单提供“打开控制台”“暂停全部自动任务”或“恢复自动任务”，以及“彻底退出”；点击或双击图标也会打开控制台。菜单仅在暂停状态变化时更新，周期检查不会不断重建正在打开的菜单。

关闭常驻选项会显示窗口并移除托盘。要结束程序，在托盘中选择“彻底退出”。退出仍遵守既有规则：本地操作尚未结束时阻止退出，等待收尾后重试；仍有所属子进程时，可以返回控制台或确认放弃追踪，应用不会代为终止外部进程。取消退出保留调度器，只有真正退出时才清除计时器和托盘。

托盘是控制台自己的后台入口，不是 Windows 服务、自启动或锁屏绕过。领取和余额任务仍要求对应厂商客户端已打开并登录，目标窗口可见、非最小化且唯一，Windows 处于可交互的未锁屏状态。隐藏控制台不会自动启动、登录或恢复厂商窗口。

## 本地 CSV 报表

“任务报告 CSV”和“余额记录 CSV”通过系统保存对话框选择本地 `.csv` 文件。取消即不写入。导出使用当前保存的数据，不触发领取或新的余额读取；内容在打开保存对话框前生成，保存完成时间不代表重新采样时间。

| 报表 | 固定字段 |
| --- | --- |
| 任务报告 | `task_id`、`kind`、`name`、`state`、`enabled`、`last_attempt`、`next_check`、`exported_at` |
| 余额记录 | `provider_id`、`provider`、`unit`、`value`、`delta`、`reason`、`sampled_at` |

时间为 ISO 8601 UTC；未发生的尝试或没有计划时间的字段为空。任务状态采用固定英文枚举，含义见上表；`enabled` 是任务本身开关，暂停期间也可能为 `true`。余额原因保留 `manual`、`scheduled`、`before_claim` 或 `after_claim`，分别表示手动、定时、领取前和领取后采样。

余额只导出每个平台当前保留的最近 100 次成功采样；没有历史的平台不生成伪造的零余额行。重新绑定、重置或改选余额字段已清除的历史不恢复。每个平台仍只有一个选定监控字段，报表按平台和单位分行，不相加、不换算。`delta` 仅为相邻同单位采样差值，可能同时包含消耗、过期或其他发放，不能当作领取收益或到账凭据。`sampled_at` 表示历史采样时刻，旧记录不代表当前余额。

报表采用 UTF-8 BOM、引号转义和 CSV 公式前缀防护。固定字段不包含本机路径、EXE 摘要、窗口标题、所选控件文字、原始错误或完整活动日志；仍包含平台使用情况和余额，应按个人数据保管。保存位置拒绝网络/设备路径、链接、非普通文件和受保护目录，通过原子替换写入；选择已有文件会覆盖该份报表。没有云上传、自动邮件发送或远程报表存储。

## 实现分工

`TaskCenterService` 根据仓库、领取、余额和活动台账快照生成视图，单独保存总控制设置；读取快照不调用厂商客户端。`RepositoryHost` 缓存仓库调度元数据及进度，固定请求由 `repository-worker.ts` 执行。`main.ts` 的单一周期循环在各阶段开始前检查总开关，按仓库 → 领取 → 余额顺序执行并共享忙碌锁；线程不健康或正在处理后台请求时暂缓这一轮检查。暂停操作可以在锁被占用时设置，Worker 在实际执行自动任务与后续清理前向主进程核对最新决定；已经进入的服务自行收尾。活动台账仍由主进程单独写入并确认结果。

`TaskTray` 只提供显示、切换暂停和退出回调，不直接调用服务或保存授权。`TaskCenterPanel` 通过固定 IPC 读取和操作，不能从渲染进程提供任意报表字段、路径写入命令或托盘菜单代码。设计与主进程边界另见 [架构说明](ARCHITECTURE.md) 和 [安全说明](SECURITY.md)。

窗口和托盘生命周期参考 Electron 官方的 [Tray 接口](https://www.electronjs.org/docs/latest/api/tray) 与 [BrowserWindow 接口](https://www.electronjs.org/docs/latest/api/browser-window)；实际构建使用工程锁定的 Electron 版本。
