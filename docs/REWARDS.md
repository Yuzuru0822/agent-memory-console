# 积分活动、自动领取与余额监控

官方资料核对日期：**2026-10-24**。活动、账号资格和客户端界面会变化；本文区分官方活动规则、控制台已实现的流程能力，以及尚未完成的真实账号验证。

## 当前控制台支持范围

控制台为七个纳管 Agent 展示九个平台条目：Qoder 国际/CN、TRAE CN/国际，以及 WorkBuddy、千问办公、智谱 ZCode、Claude Code、DeepSeek Harness。地区版本使用独立配置，不共用校准或账号状态。

| 条目 | 控制台处理方式 |
| --- | --- |
| Qoder 国际版、Qoder CN、TRAE CN、WorkBuddy | 支持绑定 Windows 客户端并校准 UI 领取流程；“验证并开启自动领取”试领成功后直接开启后续周期任务 |
| 千问办公、智谱 ZCode | 展示系统或条件赠送说明，不自动消耗重置卡、兑换现有权益或产生付费行为 |
| Claude Code | 展示需人工关联的权益说明，不代选组织或更改账单设置 |
| TRAE 国际版、DeepSeek Harness | 尚未核实可执行的主动领取流程，不提供自动点击 |

v0.4.0 的九个平台条目都提供独立余额监控配置；是否可以主动领取与是否可以读取余额分别判断。余额监控需要用户在当前 Windows 客户端中手动校准可见文字；没有可识别余额文本的客户端无法接入，不能把九个配置入口理解成九个已连接的账号 API。

这里的“支持校准”只说明程序具备相应能力，**不代表已经在这些产品的真实登录账号上领取成功或读到余额**。当前验证使用隔离的服务测试及桥接协议测试；真实账号资格、当前活动金额、实际到账、客户端 UI Automation 控件可见性、不同版本及地区的完整流程，仍需在本机逐项校准和试领确认。

UI 流程仅保存选定的 EXE、文件摘要、窗口标题、必要导航控件、明确领取控件、活动上下文和成功文案。检查窗口不会领取；记录领取按钮不会点击它。导航按钮与领取按钮分开，购买、充值、重置、邀请等操作不作为领取流程。EXE 内容变化后需要重新绑定验证。

自动任务按平台和领取窗口去重。已经领取时不再次点击，但仅观察到“已领取”不能验证首次领取流程。提交后未观察到明确成功或桥接超时，结果记为未知并暂停自动执行；未知结果不能在重启后静默重试，也不能直接再次点击“试领”。需先在客户端核对实际结果，再重新检查和记录活动规则、完成校准后手动试领。应用不把“已打开页面”“已执行点击”或一般成功提示当作积分到账证明。

校准完成后点击“验证并开启自动领取”，一次原生确认授权本次试领和成功后的周期执行。首次必须实际调用领取并观察到成功；失败或首次仅显示已领取不会开启自动。已经验证的流程也可通过开关开启或关闭。控制台与客户端均需保持打开、窗口可见、Windows 解锁；客户端更新提示、错误弹窗、验证码或登录失效会阻止操作，需先人工处理。切换账号后重新绑定和校准；程序不读取账号凭据，也不能自动区分不同账号的领取窗口。

导航跨过日切时间时，按实际提交领取的窗口记录；如果提交与成功核验跨越日切，结果保留为未知并暂停，避免把领取计入错误窗口后重复执行。窗口检查和导航记录期间也占用操作锁，完成后释放，不与其他领取流程并发操作界面。

## 余额监控的使用与含义

在平台卡片中进入“余额监控”，单独绑定客户端 EXE，在官方余额或用量页点击“检查余额窗口”。选择包含“余额”“剩余”“可用”或对应英文含义的标题，再选择对应数值：

- 标题与数值合在同一 Text 控件时，可选择同一个条目。
- 标题与数值分开时，必须是同一小容器下的直接同级 Text 控件；父容器不能是整个 Window 或 Document，直接子项最多 12 个。桥接基于原始 UIA 树保留父子关系，隐藏或未输出的父节点不会被替换成祖先。无法证明关联时拒绝读取。
- 只接受唯一明确的非负数。百分比、容量比例、日期、约数、缩写量级，以及多个匹配值都会拒绝；不把“已使用”或“已消费”字段当作余额。
- 单位由用户按客户端实际字段选为积分、Credits、CNY 或 USD；每个平台只监控一个选定字段，并显示该字段标题。套餐、活动或加量包余额可能分开，控制台不推算总额，不自动合计分类积分，不跨平台相加，也不做汇率转换。

如需自动打开余额页面，可先记录只用于查看页面的导航，最多 8 步。记录时会立即执行该导航。包含领取、购买、订阅、充值、兑换、登录或设置权限等含义的控件不能录制；唯一的精确页面名例外是 WorkBuddy 官方核实的“订阅和用量”只读入口，不放宽其内部购买、充值或续费按钮。

保存规则会记录当前观察中的数值并关闭原自动监控。成功读取一次当前余额后，可开启“自动监控余额”。刷新周期为 **5–1440 分钟**的整数，默认 15 分钟；低余额阈值可填非负数，留空不提示。只有仍在有效采样周期内、且没有读取错误的数值达到或低于阈值，才显示低余额提醒；提醒位于控制台界面，不发送外部通知。

明确读到零与没有读到数值是不同状态。未配置或尚未读取时不显示假定的 `0`；失败时保留历史值和采样时间，同时显示错误、标记过期。超过配置的读取周期，旧数据也会标记过期。每个平台保存最近 100 次成功采样，界面最多展示最近 20 次，失败不添加零值样本。

余额绑定、导航、字段和历史独立保存在 `console-data/balances.json`，不沿用 `rewards.json` 的领取授权。重新绑定、重新配置字段或重置余额监控会清除该平台原采样历史，避免将新字段或新账号与旧值比较。配置和历史为本机明文，包含窗口与控件文案、数值、单位、时间、差值和读取原因；不保存 API Key、密码或登录令牌。

### 与自动领取联动

已配置余额字段的平台，领取前尝试读取**当前页面**，不为获取前值执行余额导航；随后重新检查活动窗口再领取。提交领取后、或者观察到活动已领取后，尝试按已经保存的余额导航刷新数值。手动读取和定时监控也可使用这些只读导航。无需开启独立余额定时开关，领取前后采样仍会对已配置字段执行。

余额读取失败保留自己的错误和过期状态，不会把已经确认的领取结果改成失败，不会触发重新领取。界面“较上次变化”是两次成功余额采样的差值，可能同时包含消耗、过期或其他发放，**不是本次领取收益，也不能单独证明到账**。领取状态和余额状态分别展示。

### 选择官方余额字段

Qoder 官方说明当前可用余额位于 **Usage 页面的 Credits 卡片**；**Credits Log 仅展示获取记录**，不能把历史获得总数或单笔奖励当作当前余额。对应桌面产品、地区和版本能否向 UIA 暴露这项文字，仍需实际校准。[Qoder Credits 说明](https://docs.qoder.com/zh/Credits)

WorkBuddy 官方更新日志说明“订阅和用量”页面提供套餐概览、分类积分及资源包明细。控制台允许将这个精确页面名录为只读导航，页面内购买、充值等操作仍拒绝。选择明确的当前余额文字，不要选择套餐价格或积分包历史，也不要把 CodeBuddy 与 WorkBuddy 同账号共享余额重复相加。[WorkBuddy 更新日志](https://www.codebuddy.cn/docs/workbuddy/Changelog)

## Qoder 国际版与 CN

### 每日 100 Credits

两地区官方文档均说明：2026-09-18 10:00 起，符合条件的个人用户每天可主动领取一次 100 通用 Credits，结束时间另行公告。领取窗口是**北京时间 10:00 至次日 10:00 前**，未领取不累计、不能补领；已领取的每笔奖励自领取日起有效 30 天。

领取渠道是对应地区的**新 Qoder 桌面端**，官方描述入口为左下角用量面板 → 礼物图标。Qoder IDE、CLI 等可使用到账积分，但不属于这项每日活动的领取客户端。不要将 IDE 的 `qoder.cmd` 启动器或相似进程名自动认作新 Qoder 桌面端。

登录本身不会发放该奖励。控制台没有集成每日活动的公开 HTTP 领取 API；实现依赖用户绑定正确桌面程序后的 UI 校准。窗口切换、锁屏、活动界面变化、控件不唯一或结果不明时应停止，避免误点。

官方来源：[国际版每日 100](https://docs.qoder.com/events/100credits)、[CN 每日 100](https://docs.qoder.cn/events/100credits)。

### 国际版 1024 Community Boost：未集成自动领取

活动时间为 **2026-10-22 至 10-30 23:59（UTC+8）**。Pro 及以上个人订阅用户自动加入；Free 用户需要申请获批。见面礼为 1,024 SOTA Credits，社区目标达成可解锁其他礼包。自动加入不等于自动领取。

见面礼领取截止 10 月 30 日 23:59，可使用至 31 日 23:59；补给包须在发放后 3 天内且不晚于活动结束前领取，领取后仅 24 小时有效。不能将它安排成永久日领任务。

官方来源：[Qoder 1024 · 创造力集结](https://docs.qoder.com/zh/events/communityboost)。

## WorkBuddy / CodeBuddy

官方确认 WorkBuddy 头像菜单有 **Buddy 加油站**，用于参与当前活动获取积分，但公开页面没有提供足以固定当前每日额度、日切时间和截止日的规则。控制台因此不把网传“每日 100”硬编码成已验证活动，校准必须依据当前客户端的免费奖励页面。[官方系统设置说明](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Setting)

WorkBuddy 与 CodeBuddy 同一账号积分共享。国内免费体验版的基础 500 积分/月属于月度权益，不能作为两个产品的独立日领活动重复统计。[官方定价](https://www.codebuddy.cn/docs/workbuddy/Pricing)

海外版官方升级公告记载 Free 活跃用户每日赠送 30、Pro 每日 50；当天有对话请求视为活跃。这是限时赠送，公告未列结束日，当前账号是否适用仍待核实；它不是国内 Buddy 加油站的统一签到规则。控制台不为触发活动制造无意义对话。[海外版官方公告](https://www.workbuddy.cn/announcement/)

学生福利的公开窗口为 2026-08-24 至 10-31 23:59：通过学生资格核验后，一次发放 1,000 积分，3 个月有效且名额有限。登录、手机号授权及学生认证均在微信小程序完成，PC 端不能直接领取，不属于后台普通日领功能。[官方学生福利](https://www.workbuddy.cn/events/campus-freshman/)

### 官方 API 的实际边界

WorkBuddy 开放平台有兑换码核销 API：`POST https://www.workbuddy.cn/openapi/v2/redemptions`，要求 `user.credit.exchange` 权限、用户持有的兑换码/卡券以及幂等 `request_id`。接入前需要注册第三方应用并完成 OAuth 授权。该接口用于兑换已有兑换码，**不是签到或免费活动发现接口，当前控制台未集成**。应用密钥不能嵌入 Electron 客户端。[官方 Open API](https://open.workbuddy.cn/docs/openapi)

在官方 [CodeBuddy CLI 斜杠命令](https://www.workbuddy.cn/docs/cli/slash-commands)和 [HTTP API](https://www.workbuddy.cn/docs/cli/http-api)中未找到公开的积分签到领取接口。不能据此断言没有内部接口，但不会依赖第三方逆向端点、提取客户端登录令牌或伪造领取成功。

## 测试与真实验证

领取服务、余额服务与桥接测试分别使用临时目录、只用于格式检查的 PE 文件及模拟 Windows 桥接，不启动真实 Agent。纯原生投影测试不获取真实 UIA 窗口，原生协议测试只发送在桌面访问前就应拒绝的无效请求：

```powershell
node --import tsx --test tests/rewards-service.test.ts tests/rewards-balance.test.ts tests/rewards-windows.test.ts
```

测试覆盖平台分类、观察令牌时效、危险控件拒绝、活动上下文、明确成功判定、窗口去重及跨日切、未知结果恢复、验证后自动开启，以及余额数字解析、字段关联、零值、错误保留、过期、低阈值、定时读取和领取前后联动。实际命令、数量与结果统一见 [测试记录](TESTING.md)。通过这些测试不能证明真实活动领取、到账或实际账号余额；客户端校准与账号验证须另行记录，不应将模拟数据计为真实积分。
