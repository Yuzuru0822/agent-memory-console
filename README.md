# Agent Memory Console

用于 Windows 的本地 Agent 管理控制台，采用 Electron、React 和 TypeScript。深色界面提供七个 Agent 卡片、独立 Git 记忆与技能仓库、双向合并、定时同步、技能 junction 连接、备份与活动日志。v0.4.0 在“积分福利”中增加验证后自动领取、九个平台独立的余额校准与定时监控、低余额提示和采样历史；v0.5.0 新增任务中心、统一暂停、托盘常驻和本地 CSV 报表。v0.6.0 新增共享 MCP 模板、加密私有变量与部署回滚，以及 A2A 文本消息桥。四个平台提供可校准的免费领取流程；其他平台按实际能力说明。v0.7.1 将记忆与技能同步入口统一到“统一仓库”，移除原有共享源同步页面。

这是可运行的本地文件与进程管理工程。Claude Code CLI 按官方文档适配用户级记忆、技能路径及单次任务；v0.2.2 新增 Qoder 的用户技能、CLI 静态指令候选和 IDE EXE 启动，未接入 Qoder CLI 任务或 IDE 自动记忆。WorkBuddy、TRAE、DeepSeek Harness、智谱 Zcode、千问 Work 使用候选路径或手动绑定，尚未验证厂商协议兼容性。界面不会把文件发现结果显示成登录、额度或会话状态。完整范围见 [集成说明](docs/INTEGRATIONS.md)。

私有源码仓库：[Yuzuru0822/agent-memory-console](https://github.com/Yuzuru0822/agent-memory-console)，需使用有访问权限的 GitHub 账户。

v0.7.0 将统一仓库的预览、同步、Git 保存和总览文件检查放到独立后台线程执行，增加全局阶段进度与每页 100 项的预览。大量技能不再需要一次渲染全部列表；重复文件读取和 Git 索引写入也已减少。实际耗时仍取决于文件数量、内容大小和磁盘速度。

## 运行

便携单文件版可直接双击 `Agent-Memory-Console-0.7.1-win-x64.exe` 启动，无需另装 Electron。控制台自身不需要 Node.js；旧版 npm Claude 的 `cli.js` 仍需使用本机 Node.js。启动器每次会先解压运行文件，期间没有进度窗口，旧版在本机观察到约 30 秒等待；需要更快启动时使用下方解包版。默认构建位置为 `release/Agent-Memory-Console-0.7.1-win-x64.exe`，本版成品验证状态见 [测试说明](docs/TESTING.md)。

已取得解包版时，无需安装 Node.js：保留 `win-unpacked` 整个目录及其中所有资源，双击目录内的 `Agent Memory Console.exe`。不能只复制这一个 EXE，或直接在压缩包预览窗口内运行它。积分福利还依赖随包的 `resources/rewards/RewardBridge.exe` 与 Windows .NET Framework 组件，不能删除这个资源目录。工程中的对应位置为 `release/win-unpacked/`。

本版建议将成品输出到 `release-0.7.1/`，避免覆盖仍在运行的旧版目录。请先退出旧版，再打开 `release-0.7.1/win-unpacked/Agent Memory Console.exe`；原有用户配置会继续使用。自行重新打包默认仍输出到 `release/`。

从源码运行或重新打包时，按以下步骤操作。

使用 Windows 10/11 x64、Node.js 24 和随附的 npm。先解压完整工程，在包含 `package.json` 的目录打开 PowerShell：

```powershell
npm ci
npm run dev
```

开发模式会编译 Electron 主进程和原生积分桥接组件，在 `127.0.0.1:5173` 启动界面并打开桌面窗口。不要只用浏览器打开开发地址；浏览器没有桌面文件、进程和 Windows UI Automation 接口。修改 `electron/` 或 `native/RewardBridge.cs` 后需重新启动开发命令。

`npm run dev` 和 `npm run build` 均运行 `npm run build:rewards`。它使用系统已有的 `%SystemRoot%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`，以及同目录的 `System.dll`、`System.Core.dll`、`System.Web.Extensions.dll` 和 `WPF/` 下的 `WindowsBase.dll`、`UIAutomationClient.dll`、`UIAutomationTypes.dll`，生成 `native/bin/RewardBridge.exe`。无需为此另外下载 .NET SDK 或编译器；系统缺少上述 .NET Framework 组件时构建会失败，需先修复系统组件。构建不操作任何客户端界面。非 Windows 环境会明确跳过此组件，不能据此认为 Windows 积分功能已构建或验证。

若 PowerShell 的脚本策略阻止 `npm.ps1`，使用同名命令 `npm.cmd`，例如 `npm.cmd ci`；无需修改系统执行策略。

生产模式运行：

```powershell
npm run build
npm start
```

`npm start` 使用已有构建结果，不会自动编译。首次安装需下载 npm 包及 Electron 运行时；打包还可能下载构建工具。项目 `.npmrc` 使用 npm 官方源，并将 npm 缓存设置为工程内的 `.cache/npm`，相对于本工程解析；`.cache/` 已加入 Git 忽略规则。请将工程解压到当前用户可写的位置。

## MCP 共享与 Agent 互联（v0.6.0）

新增“MCP 与互联”页面。共享模板位于独立仓库的 `mcp/servers.json`，按客户端格式预览合并，保留已有设置并提供加密备份回滚。私有变量和桥令牌不进入 Git。

互联桥默认关闭，只监听本机；逐个启用 Agent 并设置允许发送的目标，再把桥 MCP 部署到客户端。支持 A2A 1.0 文本任务及登记原生远端。普通客户端通过 MCP 工具主动收件和回复，不能把“投递成功”当作模型已经执行。具体接入步骤、支持格式和限制见 [MCP 与 A2A 使用说明](docs/INTEROP.md)。

## 第一次使用

使用 **“统一仓库”** 管理记忆与技能同步，让多份记忆和完整技能包进入一个独立的本地 Windows 目录：

1. 在 Agent 详情中授权真实的记忆与技能路径。只读发现不自动授权写入。
2. 打开“统一仓库”，点击“选择目录并初始化 Git”，选择专用空目录；已由本应用创建的仓库也可重新打开。不要选择现有代码仓库、Agent 根目录或用户主目录。
3. 勾选 Agent 并“保存纳管选择”。已有授权记忆文件继续使用；点击“选择记忆目录”可纳管多份 `.md`、`.txt`、`.json`、`.yaml`、`.yml` 文件。
4. 点击“预览双向同步”。不同 Agent 的记忆放入独立分区 `memories/<agentId>/`，技能集中在 `skills/`。检查两端内容、共同版本与合并结果；冲突逐项选择 Agent、仓库或手动编辑，全部解决后才可应用。
5. 需要共用同一份技能时，在相应 Agent 上点击“预览连接技能”。核对导入文件、同名冲突、实际目标及原目录保留位置，再确认导入并创建 junction。仅勾选纳管不会自动替换目录。
6. 同步前后自动保存工作文件的 Git 版本；手动编辑仓库后，也可点击“提交当前变更”保存本地版本。技能自带的 `.git` 元数据单独保留，不加入中央仓库的版本记录。应用不会自动推送 GitHub 或其他远程服务，不需要本机安装 Git 命令行。
7. 按需启用自动同步，默认间隔 60 秒；可启用过期备份和临时文件清理，默认保留 30 天且至少保留 20 份。保存设置时会再次显示原生确认。自动同步仅在应用运行期间工作，冲突留待人工处理。

在两个独立副本之间，任何一端删除文件都不会删除另一端内容；下一次同步会从保留的一端补回。技能 junction 连接后访问同一份文件，其直接删除行为见下方说明。自动清理不会删除记忆、技能、Git 历史或技能连接保留的原目录。

```text
独立仓库/
  .git/                       本地版本记录
  .agent-console-repository.json  仓库标识
  memories/
    claude/                   Claude 多文件记忆
    workbuddy/                WorkBuddy 多文件记忆
    <agentId>/                其他 Agent 分区
  skills/                     共享完整技能包
```

记忆分区避免把不同 Agent 的同名文件互相覆盖，内容不会被强行合成一份 Markdown。Git 保存版本；双向同步的共同版本另保存在控制台数据目录，用于识别两端独立修改。

多个 Agent 对同一技能给出不同版本时，可点击“此 Agent 版本用于所有引用方”统一选择，包括二进制资产；也可统一采用仓库或手动合并的文本。人工预览有效期间自动同步暂缓，空闲时关闭预览或按 Escape 可取消计划；过期计划需要重新预览。v0.7.0 切换页面保留预览和选择，返回仓库页可以继续处理。

### v0.7.0：后台同步与大量文件预览

点击“预览双向同步”后，应用在后台检查仓库、扫描目录、比对文件并汇总共享技能；确认应用后，继续在后台校验、备份、写入、保存 Git 版本及同步基线。顶部状态条显示当前阶段、已用时间和可取得的文件计数，切换到其他页面仍可查看状态，也可通过状态条返回仓库页。Git 保存等没有准确文件计数的阶段只显示阶段与用时，不提供预计完成时间。

预览文件列表与“默认采用 Agent 清单”每页展示 100 项。搜索和筛选针对完整计划；“勾选当前筛选冲突”覆盖全部匹配项，批量处理仍覆盖所有已勾选项，包含其他页的选择。CSV 导出完整清单，不受当前页限制。

后台执行期间可以浏览页面，修改配置或启动另一项文件操作仍需等待当前操作结束。总暂停只阻止后续自动任务，不能取消已经开始的同步；关闭预览也不是中断写入。同步中正常退出会提示等待收尾，已启用托盘时可以隐藏窗口继续运行。若提示后台线程异常，请核对最近操作和备份后重启；应用不会自动重试不确定的写入，也不会用旧内存配置继续保存授权。

### v0.6.1：默认预选与批量处理

仓库没有文件时，单一 Agent 的文件会自动导入；多个 Agent 提供同名但不同内容的技能，仍需要选定一份共享结果。预览现在会默认采用修改时间最新的 Agent 文件。仓库已有文件且产生冲突时，如果 Agent 文件更新，也会默认采用 Agent；仓库时间较新或相同时仍留待选择。这里比较的是文件系统的修改时间，普通三方合并和单端更新仍按已有共同版本处理。

“默认采用 Agent 清单”列出相对路径、推荐来源、选择原因、两端时间和当前处理。多个 Agent 最新时间相同但内容不同时，按 Agent ID 和文件键的固定顺序预选，并显示时间相同提示。所有共享引用使用同一来源，可在详情中改选其他 Agent、仓库或手动合并。

可搜索文件/Agent、筛选全部冲突或待处理项，点击“勾选当前筛选冲突”，再批量“采用最新 Agent”“采用仓库”“恢复推荐”或“清除处理选择”。勾选一个共享文件会联动所有引用方；批量操作应用于全部已勾选项，包含切换筛选后隐藏的勾选项。仓库文件不存在时，批量采用仓库会跳过并提示。

“导出处理清单”将本次预览的全部项目和当前选择保存为 UTF-8 CSV，包含来源路径和修改时间，不包含技能、记忆或手动合并正文。请保存到纳管目录以外。预选只减少人工点击，仍需核对清单后点击“确认应用双向同步”；后台自动同步遇到冲突继续暂停。预览后内容、链接或推荐依据的修改时间改变时，需要重新预览。

### v0.7.1：统一同步入口与升级说明

侧栏不再提供“记忆与技能”页面；概览中的共享源选择、单向同步按钮、共享源版本指纹和“与共享源一致”比较也已移除。概览继续展示 Agent 本地路径与文件检查结果，新的记忆与技能同步从“统一仓库”发起。路径可读或已纳管不代表两端内容已经一致，需要通过双向预览检查实际差异。

旧模式把同一份 Markdown 分发给多个 Agent，当前界面不再提供这一单向广播操作。统一仓库继续使用 `memories/<agentId>/` 独立记忆分区，不会自动把不同 Agent 的记忆混合或覆盖成同一份；完整技能包在 `skills/` 中共享。

升级保留旧共享源配置、原始源文件、Agent 授权与历史备份，不自动移动、复制或删除它们，也不会自动把旧共享源设为统一仓库。需要纳管的现有内容，应先确认各 Agent 的实际授权路径，再在统一仓库中预览导入。

“备份快照”仍可手动备份并对历史快照生成恢复预览。恢复需要确认，目标必须保有当前授权；只还原快照中已有的文件，不删除后来新增的文件。移除旧同步页面不影响这条恢复流程。

### 历史说明：原有共享源（v0.7.0 及更早版本）

以下记录旧版本的操作与语义，v0.7.1 已移除相应同步入口；当前使用方式见上方“第一次使用”和升级说明。

1. 点击卡片的“查看检查与配置”。自动发现只检查内置候选位置，未发现时可以手动选择真实路径。
2. 对需要管理的记忆文件、技能目录点击“选择并授权”，并在系统对话框确认。记忆文件必须是已有的 UTF-8 `.md` 文件，技能目标必须是已有目录。技能目录可以包含本地符号链接或 junction；确认框会展示实际目录和链接指向。空目标请先在资源管理器创建；选择候选路径也需明确授权。
3. 在“共享记忆源”选择一份作为来源的 Markdown；需要同步技能时，再选择“共享技能源”。共享源与目标技能目录不得相同或互相嵌套。
4. 勾选目标 Agent，点击“预览记忆同步”或“预览技能同步”。查看每个文件的当前内容、写入后内容以及跳过原因。
5. 点击“确认并执行”，核对第二次系统确认中的实际目标路径。现有目标会先备份，再逐文件写入并校验。预览五分钟后失效，来源、目标或授权配置变化也会阻止旧预览执行。
6. 在“备份快照”可手动备份，或对已有快照生成恢复预览。恢复仍需确认，且目标路径必须保持授权。恢复不会删除同步后新增的文件。

旧兼容模式是从共享源向目标的单向文本复制；同名文件被替换，不做内容合并，也不会删除目标独有文件。它只复制允许的文本，不完整搬运技能包。源链接会读取实际文本内容，目标已有链接则写入已授权的实际文件；此模式不创建或替换链接本身。完整技能导入与 junction 创建使用“统一仓库”的独立流程。

顶栏的“30 秒自动检查”只是状态刷新：空闲每 30 秒，有所属进程运行时每 2 秒。统一仓库的自动同步需另行开启；两者设置独立。“路径完整”表示记忆与技能路径可读取，不表示 Agent 已安装完整、已登录或已经运行。

## 技能目录中的符号链接和 junction

“统一仓库 → 预览连接技能”可以将 Agent 整个技能入口改为指向仓库 `skills/` 的 junction。先导入完整文件包，包含脚本和二进制资源，但不执行这些文件。已有链接中的正常文件会导入为实际文件；失效或循环入口单独提示，其原入口仍保留在完整原目录备份中。仓库内部使用普通目录和文件，不再叠加新的链接。

连接后，Agent 与仓库直接访问同一份技能，Agent 自身删除或修改技能也会直接改变仓库。这是 junction 的共享文件行为；“不传播删除”适用于两份独立文件之间的同步。请用 Git 提交保存需要保留的版本。点击“解除连接并恢复原目录”可恢复连接前入口，仓库中的新增和修改继续保留，不反向删除仓库内容。

符号链接是指向另一处文件或目录的入口；Windows junction 是指向目录的另一种入口。把多个 Agent 的技能入口连接到同一份共享技能目录是正常用法。v0.1.2 会沿本地链接进行只读检查，按实际文件和目录去重统计，不再仅因为存在链接而显示“待检查”。技能数量来自 `SKILL.md` 文件名检查，不读取技能正文，也不受同步的 200 个文本文件限制；一次检查最多遍历 20,000 个条目和 20 层，达到限制或遇到断链、循环时会提示结果不完整。

升级后，已保存的技能路径继续使用。打开 Agent 详情，在技能目录处点击 **“授权技能链接”**，核对系统确认框中的实际根目录和各链接指向，确认后才能对这些实际目标同步或备份。旧版授权不会自动扩大到链接指向的位置；首次选择带链接的目录时，“选择并授权”会一并展示这些映射。旧共享技能源的配置继续保留，但 v0.7.1 不再提供共享源区域。

写入共享目录会影响所有使用同一链接目标的 Agent。链接改指其他位置后需要重新授权并重新预览。仅支持本地文件和目录；网络、设备路径、断链、循环或受保护的写入目标会被拒绝或提示检查不完整。记忆文件、普通 EXE 和工作目录仍使用各自严格的路径检查，不因技能链接支持而放宽。

### 技能自带 Git 仓库

v0.2.1 的技能连接迁移支持技能根目录或其子目录中的普通 `.git` 目录。显式导入时保留内层仓库的提交历史、分支和远程配置，原技能目录及其 `.git` 也保留在迁移备份中。控制台只复制元数据，不调用内层仓库的 hooks，不执行远程操作，也不运行其中配置的命令。

预览会提示完整保留的 Git 仓库数量，不展示 Git 配置正文。目标已有同名 `.git` 时，完整元数据相同可复用；历史或配置不同则按整个仓库报冲突，在写入前停止，不提供逐文件合并 `.git`。请先统一双方的仓库版本，或使用不同的技能子目录后重新预览。

中央仓库只记录技能工作文件，不把内层 `.git` 元数据或 Git 子模块引用加入提交；中央仓库的历史不能用于恢复内层 Git 元数据。普通工作文件仍参与双向合并，两个独立副本之间的手动或自动同步均排除 `.git`，不会合并或传播提交、分支、远程配置。需要携带原历史时使用上述显式技能连接迁移。

junction 连接后，从 Agent 路径或仓库路径访问的是同一份技能与内层 Git。用户自行使用 Git 修改历史或远程配置，会直接影响所有连接到该目录的 Agent。控制台不会代为执行这些操作。

迁移要求独立完整工作树。以下项目会被明确拒绝：外置 `.git` 指针文件；`.git` 中的 `commondir`、`gitdir`、`worktrees`、`modules`、`objects/info/alternates` 或 `http-alternates`；配置中的 `include/includeIf`、`core.worktree`、`core.hooksPath`、`extensions.partialClone` 或 `remote.*.promisor`；Git 元数据中的链接、junction 和 `.lock` 锁。请先准备不依赖原路径、对象完整的独立 clone；遇到锁时先等待 Git 操作完成，确认残留锁可安全处理后再迁移。不要直接复制 `.git` 指针文件或在 Git 仍写入时迁移。

完整迁移仍受 5,000 个文件、总计 256 MiB 限制；普通文件最多 32 MiB，仅 `.git/objects/pack/*.pack` 文件放宽至 128 MiB。Git 配置另需为不超过 1 MiB 的有效 UTF-8 普通文件。超出限制会停止迁移并提示，不会静默省略历史。

## 启动 Agent

在 Agent 详情中选择并授权本地 `.exe` 和运行工作目录，然后点击“启动程序”。除 Claude 外的六个适配器只提供通用 EXE 启动，不向厂商派发任务。

Qoder 默认检查 `~\.qoder\skills` 与 IDE EXE。它的 `~\.qoder\AGENTS.md` 候选仅表示 CLI 用户静态指令，不是 IDE 自动记忆；项目文件、规则或多文件记忆目录，以及地区版、自定义配置目录，均需手动选择实际路径。本机 IDE 可从 PATH 中的 `bin` 父目录发现；`qoder.cmd` 不会被执行，也不作为 CLI 任务入口。

Claude Code 支持原生 Windows CLI 和 `npm install -g @anthropic-ai/claude-code` 安装，需自行完成登录。原生版绑定 `claude.exe`。npm 版在详情的“npm 安装”区域点击“授权检测到的 npm 安装”，核对版本、实际程序以及需要时的 Node.js 路径；随后选择运行工作目录、填写任务并点击“运行任务”。未自动发现时，在“Claude 程序（EXE / claude.cmd）”中手动选择安装目录的 `claude.cmd`。

npm 自动发现检查环境中的 npm prefix、`%APPDATA%\npm`、nvm 路径和最多 128 个 PATH 目录，不执行 npm 或启动脚本。支持包内 `bin/claude.exe` 和旧版 `cli.js` + Node.js 两种结构，直接启动解析后的程序，适用于带空格的自定义安装目录。安装入口或 Node 路径变化后需重新授权；未知包结构会明确拒绝。

两种安装方式都使用固定参数 `-p`，任务经标准输入传入，展示输出和退出码。控制台不会安装 Claude、读取其登录凭据或绕过 Claude 的权限规则。任务可能联网、产生费用或修改工作目录中的文件；确认启动前请阅读任务内容。

`claude.cmd` 仅用于定位受支持的 npm 包，不读取或执行脚本正文。不执行任意 `.cmd`、`.bat`、PowerShell 脚本、快捷方式或命令字符串。除 Claude 外的六个适配器仍只接受 EXE。控制台只追踪自己启动的直接子进程。“停止所属进程”不会结束外部已运行程序或整个进程树；桌面程序启动器退出后，独立运行的应用状态可能未知。关闭控制台后也不能恢复此前的进程追踪。

## 积分福利与余额监控（v0.4.0）

七个 Agent 对应九个平台条目，地区版本各自保存配置：

| 范围 | 当前能力 |
| --- | --- |
| Qoder 国际版、Qoder CN、TRAE CN、WorkBuddy | 四条可校准的客户端 UI 领取流程；“验证并开启自动领取”成功后自动开启后续周期任务 |
| 千问办公、智谱 ZCode | 介绍系统或条件赠送权益，不代替登录、不消耗重置卡或兑换已有权益 |
| Claude Code | 介绍需人工关联的权益，不代选组织或修改账单设置 |
| TRAE 国际版、DeepSeek Harness | 尚未核实可执行的主动领取流程，不自动点击 |

全部九个平台另提供独立的只读余额监控配置。它需要在实际客户端窗口中手动选择余额文字，不是开箱即连的账号或余额 API；没有可识别余额文字的客户端不能完成校准。**真实账号的领取、到账与余额读取尚未完成验证**。当前活动资格、金额和界面以客户端为准，官方来源与活动边界见 [积分活动与余额说明](docs/REWARDS.md)。Qoder 每日活动要求对应地区的**新 Qoder 桌面端**，不能把 Qoder IDE 或 CLI 启动器当成领取客户端。

1. 自行打开正确的 Windows 客户端并登录，在“积分福利”中单独绑定其 EXE。文件管理或程序启动的既有授权不会自动授权领取。
2. 检查可见、非最小化的窗口，按需要记录导航控件。**记录导航会立即执行该导航；记录领取按钮只保存选择，不会点击领取。**
3. 在活动页选择明确的领取按钮、活动上下文和成功文案，核对每日重置时间。不要把购买、充值、重置或邀请按钮作为免费领取入口。
4. 点击“验证并开启自动领取”并确认。程序试领一次，在同一活动上下文中观察到明确成功后，会直接开启后续周期领取，无需每天手动点击。也可单独试领后再开启开关。仅看到“已领取”不能验证首次领取流程。

自动执行只在控制台运行、客户端窗口可用且桌面未锁定时工作；彻底退出应用后停止。开启托盘常驻后关闭窗口仍会调度，统一暂停时等待恢复。锁屏或无法唯一定位窗口/控件时拒绝操作。客户端的更新提示、错误弹窗、登录失效或验证码需先由用户处理，再重新检查。领取提交后未能确认结果会保存为“未知”并暂停自动执行，重启也不会静默重试；需先到客户端核对，再重新校准。EXE 更新需重新绑定；切换账号也应重新绑定并校准，控制台不识别账号身份，去重依据是平台和领取窗口。

### 配置余额监控

1. 在任一平台卡片打开“余额监控”，单独绑定可信客户端 EXE，手动打开官方余额或用量页面后点击“检查余额窗口”。余额与领取配置互相独立。
2. 选择明确的余额标题和实际数值。合并文字如“可用积分 1,200”可同时选为标题和数值；分开的标题、数值必须属于同一小容器的直接同级文字。已用量、套餐上限、活动奖励额度、购买价格和获取历史不能代替当前余额。
3. 选择实际单位：积分、Credits、CNY 或 USD。设置 5–1440 分钟的读取周期（默认 15 分钟），可填非负的低余额阈值，留空关闭提示。保存规则会记录一次当前观察中的余额；成功读取后可开启“自动监控余额”。
4. 若需切换页面，先记录仅用于查看余额的导航；记录导航会立即执行。WorkBuddy 已核实的精确页面名“订阅和用量”可作为只读入口，页面内的购买、充值等操作仍拒绝；其他涉及订阅、购买或登录等操作的入口不允许录制。窗口、账号或程序版本变化后重新绑定校准，避免混合账号历史。

每个平台监控一个用户选定的余额字段，显示字段标题、数值、单位、采样时间和与上次采样的差值。套餐、活动与加量包余额可能分别显示，控制台不推算总额，不合计跨平台积分，也不换算不同单位。明确读到 `0` 才显示零；未配置或未读到不填零。失败时保留上次值并显示失败或过期，超过读取周期也会标记过期；只有新鲜数据达到或低于阈值时显示低余额提示。每个平台保留最近 100 次采样，界面展示最近 20 次。

已经配置余额的平台，在领取前会尝试只读当前页面，不为采样跳转页面；领取提交后或观察到已领取，会按余额导航尝试刷新。余额读取失败不会撤销已经核验的领取结果，也不会据此再次领取。差值可能包含使用消耗、到期或其他发放，**不能当作本次领取收益或到账证明**。

## 任务中心与后台运行（v0.5.0）

打开“任务中心”可统一查看仓库同步、过期备份清理、九个平台的领取与余额任务。列表说明当前状态、等待原因和已有的最近/下次检查时间，支持类型筛选、文字搜索和“只看需要关注”。“待处理问题”汇总同步冲突、授权变化、领取结果未知、余额读取失败、过期和低余额等问题，重复刷新不会把同一问题累加；点击“前往处理”进入相应功能页。

- **统一暂停**：选择 15 分钟、1 小时或暂停直到手动恢复，只阻止后续自动执行。已经开始的操作正常收尾，手动同步、试领和读取仍遵循原有授权及串行锁。暂停不改各任务的启用开关；恢复也不会开启原本关闭的任务或重试未知领取。
- **重启与到时恢复**：暂停状态保存在本地，重启后仍有效；定时暂停到期后，原先启用的任务在应用运行时恢复调度。应用退出期间不会执行或唤醒电脑。
- **托盘常驻**：默认关闭。勾选“关闭窗口后留在系统托盘”后，关闭窗口只隐藏控制台；点击托盘图标可重新打开，右键菜单可暂停/恢复自动任务或“彻底退出”。托盘创建失败不会隐藏窗口。彻底退出仍检查在途操作及所属进程；取消退出不会停掉自动调度。
- **本地报表**：任务报告 CSV 导出固定的状态与时间字段；余额记录 CSV 导出已保存的采样，每个平台最多最近 100 条。选择本地保存位置，不包含本机路径、窗口/控件文案或原始错误日志。余额按平台和单位分行，不合计；差值不是领取收益。

托盘运行不改变客户端前提：积分领取和余额读取仍需要正确客户端已打开、已登录、窗口可识别且 Windows 未锁屏。当前真实账号的领取、到账与余额读取仍未验证。配置恢复、状态口径和报表字段见 [自动任务设计与使用说明](docs/AUTOMATION.md)。

## 本地数据

应用通过 Electron 的 `userData` 定位数据目录，在其下创建 `console-data/`；默认通常为 `%APPDATA%\Agent Memory Console\console-data`。以应用“备份快照”中的数据目录定位结果为准。

```text
console-data/
  config.json                 授权路径、统一仓库、自动化设置及保留的旧共享源配置
  activity.jsonl              操作台账
  rewards.json                积分平台配置、校准选择、领取窗口状态与结果日志
  balances.json               独立余额配置、单位、阈值、读取状态与最近采样历史
  task-controls.json          统一暂停、到期时间与关闭窗口留在托盘的设置
  backups/<快照 ID>/
    manifest.json             原逻辑路径、实际目标和内容校验值
    0.txt, 1.txt, ...          备份的原始文本字节
  repository-data/<仓库标识>/  统一仓库的同步状态、共同版本、备份和连接回执
```

控制台没有云端文件同步或遥测实现。显式发送到登记的 A2A 远端会传输消息正文。原有记忆/技能配置、日志、备份和余额历史为本机明文；新增 MCP 私有变量、配置备份及桥令牌/消息正文使用 Windows 加密存储。客户端配置可能仍包含明文凭据，应按原始资料的敏感程度保护。日志含路径、操作结果及余额采样数值，不保存任务正文；CLI 输出仅保留在当前进程内存，最多 32,000 字符。积分与余额配置保存选定窗口标题和控件文案，不读取或保存 API Key、密码输入框、登录令牌或客户端凭据文件；可见文案仍可能含个人信息。打开官方活动链接及客户端领取会使用浏览器或第三方客户端的网络连接。

## 常见问题

- **显示“未配置”**：文件候选只覆盖少量固定目录；npm Claude 额外检查有限的 PATH 与 npm prefix，Qoder IDE 额外检查有限的 PATH / `bin` 父目录，不扫描注册表或全盘。通过详情手动选择实际位置。
- **有文件但同步被跳过**：只读发现不授予写权限。请先选择并授权目标，随后重新预览。
- **旧版提示“技能目录包含链接或 junction”**：升级至 v0.1.2 后可直接检查和统计本地链接中的技能。需要同步或备份时，在详情点击“授权技能链接”，核对实际指向；无需拆除链接。
- **链接已授权但提示重新授权**：链接的实际指向或目录结构发生了影响授权的变化。核对新位置，重新授权后生成新预览。
- **预览后文件发生变化**：重新刷新并生成预览，不要直接重复执行旧计划。
- **大量文件仍需要等待**：v0.7.0 在后台执行扫描、校验、备份和 Git 保存，可通过顶部状态条查看阶段并切换页面；磁盘工作仍需要时间。不要为了加快任务而强制结束进程。后台线程异常时先核对结果与备份，再重启并重新预览。
- **积分桥接不可用**：源码运行先执行 `npm run build:rewards`；成品检查完整的 `resources/rewards/RewardBridge.exe` 和系统 .NET Framework 组件，不要只复制主 EXE。
- **积分无法检查或结果未知**：先解锁桌面，打开已绑定客户端并保持窗口可见。若已提交领取却显示未知，先在客户端核对实际结果，再重新校准，不要反复点击试领。客户端更新或账号切换后也应重新绑定或校准。
- **余额未读取、失败或已过期**：不代表零余额。检查当前客户端是否显示明确的余额文字、是否被弹窗遮挡，以及窗口标题和版本是否变化；先处理客户端问题，再“读取最新余额”或重新校准。余额配置不会自动授予领取权限。
- **自动任务没有运行**：在“任务中心”查看总暂停、任务自身开关、校准等待和待处理问题。下次检查时间不是保证执行时间；在途操作、未完成预览、锁屏或客户端错误仍会推迟执行。
- **关闭窗口后仍在运行**：检查任务中心的托盘常驻设置。要结束程序，从托盘右键菜单选择“彻底退出”；若有在途操作，等待收尾后再退出。
- **任务控制配置需要恢复**：`task-controls.json` 无法读取或保存时，自动任务保持暂停且不启用托盘隐藏。检查数据目录后，在任务中心“恢复自动任务”并确认重建控制设置；各任务已有授权与开关保留。活动台账校验失败时仍不能恢复。
- **台账校验异常或超过 32 MiB**：同步写入、备份、启动和路径授权变更会被阻止。关闭应用，保留完整 `console-data` 备份并检查 `activity.jsonl`；需归档时将原台账完整移出数据目录后重启，新日志会形成新的链。不要将手工改写的旧日志当作完整审计记录。
- **源/目标很大或包含脚本**：检查统计、历史文本备份恢复与完整仓库同步采用不同限制。历史文本流程上限 200 个文件 / 16 MiB；统一仓库支持 5,000 个文件 / 256 MiB、普通单文件 32 MiB，技能迁移的 `.git/objects/pack/*.pack` 可至 128 MiB。脚本和资源只保存字节，不执行。文本合并另受 1 MiB 限制。详见 [安全限制](docs/SECURITY.md)。
